考研专业课里最难复习的不是背书，是**不知道考什么**。学校不公开考纲，真题散落在几份 PDF 里，翻开能看懂，合上就忘，也说不清哪些考点每年都考。

于是我拿七年真题做了一次彻底的数据化：把每张卷子转成文字，把每个考点编上号，把每道题拆成行，再让 AI 算出哪些考点是高频的、哪些题其实在换着参数反复考。最后产出了三份可以直接打印的复习材料。

这篇文章记录整个过程，包括每一步的规则、踩过的坑，以及一次差点把 C 盘撑爆的意外。

## 一、起点：先把文件名统一

资料一开始乱得没法用。文件夹里躺着几份 PDF，命名各不相同，有的还是哈希文件名，光看名字根本不知道是哪个年份。

我的第一条指令很朴素：

> 复习和真题pdf这个文件夹里的pdf命名给我统一一下根据内容

AI 的做法不是猜文件名，而是**先读内容**：先用文本提取读首页，扫描版读不出来就上本机 OCR，最后人工视觉核对。靠这个流程识别出：

- 6 份是西安工程大学 2019–2025 年的 623 量子力学科目真题（当时缺 2022）；
- 1 份是按章节整理的量子力学期末复习问答资料；
- 那个哈希文件，其实是 2019 年真题。

于是统一成 `年份-学校-科目代码与名称-资料类型.pdf`。后来我又补了 2022 年的，AI 同样先读首页确认、再重命名。**最终 2019–2025 七年连续齐全。**

:::tip[重命名也要「改前校验、改后校验」]
每次批量改名，AI 都会比对前后哈希，确认只是改了名字、内容一个字节没动。这个习惯是我要求的——批量操作最怕的就是「顺手改坏」。
:::

## 二、搭一个能长期用的目录结构

文件名统一之后，我定了一个固定的工作区结构：

```text
qm-623/
├── raw/          原始 PDF
├── pages/        真题按页渲染的 PNG
├── pages-ref/    复习资料渲染的 PNG
├── transcript/   逐页转录文本
├── data/         结构化数据
├── analysis/     分析结果
└── output/       最终成品
```

为什么要这样分？因为这件事的本质是一条流水线，每一段都要能单独重跑：

```text
PDF  →  渲染成图  →  转录成文本  →  结构化  →  分析  →  排版
```

某一步出问题，只重跑那一步就行，不用从头再来。这也是后来所有工作的基础。

7 份真题各 4 页，按 300 DPI 渲染出 **28 张 PNG**；复习资料 14 页渲染成 `ref-p01`–`ref-p14`。渲染完我先要求输出页数清单，确认无误才继续。

## 三、转录：最重要的一条规则是「不许猜」

转录量子力学试卷是整个项目里最容易翻车的一步。公式密集，而有几个符号在扫描件里**天然难分辨**：

- ℏ（约化普朗克常数）和 h（普朗克常数）
- 算符的帽子 ^ 到底有没有
- 上下标的位置、正负号
- ψ 和 φ
- 积分上下限、求和指标的范围

我给出的规则里，第二条是加粗强调的：

:::important[不确定就标 `[?]`，绝对不许猜]
看不清、有歧义、不确定的字符，**原地写 `[?]`**。不要猜测，不要补全成「看起来合理」的内容。宁可整个公式只写 `[?]`，也不要写一个你不确定的符号。
:::

同时还有几条硬性要求：

| 规则 | 内容 |
| --- | --- |
| 公式格式 | 一律用 LaTeX，行内 `$...$`，独立成行 `$$...$$` |
| 原样保留 | 不修正原题里的笔误或印刷错误 |
| 层级 | 保留「一、二、三」「1. 2. 3.」「(1)(2)(3)」的题号层级 |
| 分值 | 卷面标了分值的，用 `【x分】` 标在题号后 |
| 插图 | 写 `[图：一句话客观描述]` |
| 输出 | 只输出转录内容，不解题、不评论、不补充说明 |

我先让它只做一页（2019 年第 1 页）作为样本，自己核对通过后，才让它按同一规则批量处理剩下 27 张。

结果很直白：

| 项目 | 数量 |
| --- | --- |
| 转录完成的真题页面 | 28 页 |
| 复习资料页面 | 14 页 |
| 真题转录中标为 `[?]` 的位置 | 11 处（集中在 2019-p01 的 8 处、2019-p03 的 2 处、2022-p01 的 1 处） |
| 复习资料转录中标为 `[?]` 的位置 | 1 处 |

七年真题、几百个公式，需要人工确认的位置只有十余处，而且集中在扫描质量较差的那几张卷子上（比如 2019 年那几张，字形本身就无法可靠区分 ℏ 和 h）。**这不是因为 AI 猜得准，而是因为它被要求「猜不准就说不知道」。**

## 四、把复习资料变成 97 条可追溯的知识点

十四页复习资料是 PPT 导出的，本身有层级：章 → 节 → 知识点。我要求按原结构提取一份清单，每条给唯一编号：

> 按 PPT 原有的层级结构组织（章 → 节 → 知识点），每条知识点给一个唯一编号，格式 T01、T02……保留原始措辞，不要改写、不要合并近义项，只提取知识点名称，不要摘录例题和解释。

最终得到 **97 条知识点、6 个大类**，编号 T01–T97。

这个编号系统是整个项目的关键。后面所有题目、统计、标注都挂在这 97 个编号上，所以它必须**稳定、唯一、可追溯**。

## 五、275 道题：把每张卷子拆成一行

有了转录文本和知识点编号，下一步是把七年真题结构化。我设计了 10 个字段：

```text
年份, 大题号, 小问号, 题型, 分值, 知识点编号,
知识点名称, 核心公式或方法, 题干摘要, 备注
```

规则里有几条是刻意的「保守设计」：

- **一道大题下每个小问单独占一行**，不合并；
- **知识点编号必须从 `topics.md` 里选现有的**，不许新造；
- 一道题涉及多个知识点，编号用分号隔开，**主考点排第一**；
- 在 `topics.md` 里找不到对应项的，编号填 `NEW`，备注写「PPT 未覆盖」；
- 分值是卷面没标的，填「未标注」，**不要估算**；
- CSV 用 UTF-8 with BOM 编码（为了 Excel/WPS 打开不乱码）。

结果：**275 行**，逐年分布 36 / 35 / 38 / 42 / 41 / 41 / 42。

### 拆得太细怎么办？让它自己核对

拆行有个风险：会不会拆过头，把一道题拆成好几行？

我没有直接相信结果，而是要求做一次抽查核对：

> 打开 `2019-p01.md` 和 `2019-p02.md`，数一下卷面上实际印刷的题号有多少个，与 `questions.csv` 中 2019 年的 36 行做对照。如果 CSV 行数多于卷面小问数，指出多出来的行是怎么产生的。

核对结果很清楚：

| 计数口径 | 数量 |
| --- | ---: |
| 卷面主题号 | 34 |
| 含明示 `(1)(2)` 的最小小问 | 35 |
| CSV 行数 | 36 |

多出来的一行，来自 Q31 把「什么是康普顿效应？」和「为什么用 X 射线来进行实验？」拆成了两个小问——卷面没印 `(1)(2)`，但那是两个独立的问法，属于合理的拆分。

:::tip[为什么要费这个劲]
拆行粒度直接决定了后面的统计是否可信。如果 36 行里混着 10 行「拆过头」的重复，那「哪些考点高频」的结论就是假的。**宁可慢一步核对，也不要拿错数据往下走。**
:::

## 六、让数据自己说话：频次和重复题

结构化之后，分析就是纯计算了。我让它输出两份东西。

**第一份是考点频次。** 每个考点七年里考了多少次、出现在哪些年份、以什么题型出现。算完之后按频次分档：

| 档位 | 条数 |
| --- | ---: |
| 高频 | 30 |
| 中频 | 25 |
| 低频 | 23 |
| 零命中（七年未考） | 19 |
| 合计 | 97 |

频次最高的几个考点很说明问题：

| 知识点 | 出现次数 |
| --- | ---: |
| T49 几个常见的力学量算符的本征函数和本征值 | 32 |
| T19 波函数的统计解释 | 19 |
| T50 一般求解力学量算符平均值的两个公式 | 17 |
| T33 定态一维无限深势阱和线性谐振子薛定谔方程的解 | 16 |

**第二份是重复题比对**，这是我觉得最有价值的部分。它把七年里的题横向拉齐，找出三类关系：

| 类别 | 组数 | 涉及题数 |
| --- | ---: | ---: |
| 原题重现（几乎一字未改） | 7 | 14 |
| 参数变化（换数字、换条件） | 19 | 90 |
| 表述变化（换题型、换问法） | 28 | 101 |
| **合计** | **54** | **205** |

205 道题 / 275 道题 = **74.55%**。也就是说，七年真题里超过七成的题目，都是同一个考点换着花样考。

举几个真实的例子：

- **原题重现**：2019 年二、22 和 2024 年三、35，都是「波函数的标准条件是____、____、____」，只差标点和空线样式；
- **参数变化**：7 道题全都是「给出本征函数展开式的系数，求指定本征态的概率」，只是把系数、项数和目标态换了一下；
- **表述变化**：6 道题都考「定态薛定谔方程是哈密顿算符的本征值方程」，分别改成了填空、选择、判断、简答。

:::important[这份分析真正的用处]
它把「复习」变成了一件有优先级的事。30 条高频考点占了绝大多数分值，19 条零命中考点七年一次都没考过——**先看什么、可以跳什么，第一次有了依据。**
:::

## 七、三次追问：把「差不多」变成「可核对」

分析做出来之后，我连续追问了三轮。这三轮才是数据真正变可靠的地方。

**第一轮：覆盖率是多少？**

> 各年真题中的每个题所对应的知识点是不是都包含在你给我的高频中频低频 uncovered 知识点里面？

结果：275 道题 **100% 覆盖**（264 道来自 T01–T97，7 道纯 `NEW`，4 道两者都有），没有游离在分类体系之外的题。

**第二轮：那些 `NEW` 是什么？**

`NEW` 是「真题考了，但复习资料里没有」的考点。11 条记录去重后是 **5 个考点**：

| 考点 | 出现次数 |
| --- | ---: |
| 氢原子量子态数与能级简并度 | 5 |
| 概率流密度 | 3 |
| 时间与动量的不确定关系 | 1 |
| 量子力学第五条基本假定 | 1 |
| 近代物理学两大划时代里程碑 | 1 |

这 5 条被我单独整理成 `uncovered.md`，按出现次数降序排列。**它是复习资料的缺口清单，也是我复习时最该补的地方。**

**第三轮：被 `[?]` 挡住的那道题呢？**

有一道题（2023 年一、5）因为字符识别不确定，考点没法判断，被标成了「待补」。我要求重新回原图核对：

> 重新读取对应的原图，只针对该题重新转录，把挡住判断的 `[?]` 尽可能识别出来。规则不变：仍然不确定的保持 `[?]`，不要猜测。

重新放大原图后确认那是一个动量算符符号，遮挡没有覆盖关键变量，于是该题从「待补」转成了正式考点。**最终「待补」条目清零。**

## 八、一个真实的意外：C 盘被撑爆了

转录到一半，我发现 C 盘空间突然告急。

我去问了另一个会话：

> 刚刚那个对话往我 c 盘里写入啥了，咋 c 盘爆了

排查结果是：**不是文件写满了，是内存不够。**

| 项目 | 数据 |
| --- | --- |
| C 盘分页文件 `pagefile.sys` | 从 17.4 GB 涨到 23.6 GB，增加约 6.2 GB |
| 批量 OCR 进程 | 私有内存申请约 24.6 GB，仍在运行 |
| OCR 环境与模型 | 分别 4.75 GB、2.29 GB，都是原有占用 |
| 会话日志 | 约 29 MB |
| 生成的文件 | 全部在 D 盘 |

原因是批量 OCR 吃掉了大量内存，Windows 为了兜底不断扩张虚拟内存文件。**真正被「写入 C 盘」的，其实是系统分页文件，不是项目文件。**

:::warning[几个很实用的结论]
1. 大批量处理图片/OCR 时，内存占用会直接转化成磁盘占用，**C 盘会先扛不住**；
2. 遇到这种情况要停任务、降温，**绝对不要手动删 `pagefile.sys`**；
3. 我后来把中间产物和临时文件都固定放在 D 盘，从流程上绕开这个问题。
:::

## 九、最后一步：把数据排版成能打印的复习材料

数据齐了，最后是把它们变成能带进自习室的东西。我用 Typst 排版，生成了三份 PDF：

| 文件 | 内容 | 页数 |
| --- | --- | ---: |
| `ppt-annotated.pdf` | 复习资料逐条标注考点档位、考过几次、对应哪年哪题 | 75 |
| `mother-questions.pdf` | 参数变化的母题，每组一页，标注改了哪些参数 | 19 |
| `repeat-questions.pdf` | 原题重现的对照，同组题目上下排列便于逐字比较 | 7 |

排版要求也很严：

- LaTeX 公式必须渲染成**数学符号**，不能露出源码；
- 中文用系统中文字体，确认**无方框乱码**；
- 转录里的 `[?]` 原样保留并**标红**；
- 档位配色区分：高频红 / 中频橙 / 低频灰 / 零命中浅灰。

其中 `ppt-annotated.pdf` 改过一版。第一版做完我发现：零命中的 19 条知识点也混在正文里，占篇幅又没价值。于是要求删除这 19 条，改成两个动作——

1. 正文只保留考过的 78 条知识点；
2. 每条知识点后面追加「历年真题」区块，**一道不漏**；
3. 涉及多个知识点的题，**在每个相关知识点下都完整出现一次**（宁可重复，不能遗漏）；
4. 文档末尾加一张覆盖率校验表。

最终结果：**275/275 道题全部覆盖**，因为多考点重复收录，共生成 **429 个真题区块**，成品 75 页。

排版过程中还发现一个细节问题：有些真题框在页面底部只留下题头，正文翻到下一页。AI 把每个题框设成整块换页，重新编译后才算完成。

## 十、这件事教会我的

回头看，这个项目里 AI 做的是大量重复劳动：转录、拆行、比对、统计、排版。但真正决定结果质量的，是我定的那几条规则：

**一、把「不确定」当成一等公民。** 十几处 `[?]` 比几百处猜测有价值得多。宁可承认看不清，也不要编一个看起来像的答案。这个原则在手写识别、数据抽取、公式转录里是通用的。

**二、每个结论都要能追溯到原始数据。** 知识点有编号、题目有出处、统计有口径。所以后来我才能连着追问三轮覆盖率，并且每次都得到可核对的结果。

**三、先小样本验收，再批量执行。** 转录先做一页、确认质量，再处理剩下 27 页。这一步省下的返工时间，远比多做一次核对要多。

**四、数据错了，后面全白干。** 拆行粒度、知识点映射、`[?]` 标注——这些环节只要有一处是「差不多就行」，最后的频率统计就是不可信的。

现在我手上这套东西，说实话比任何一本教辅都更贴合我报考的学校：它只包含这七年真正考过的 78 个考点、5 个资料缺口、19 组换着参数考的母题，以及那 7 组一字未改的原题。

**这就是用自己的真题，做自己的考纲。**
